# 简报 TSUNAMI-001：海啸原理科普网页（3D 交互讲解）

## 任务

用户原话：「做一个海啸原理的科普网页，可以用一个 3D 模型来讲解。」

理解：交付一份中文单页 Web 科普作品，核心是一个**可交互的 3D（WebGL）场景**，用三维模型把海啸从「海底地震发生」→「波在深海传播」→「浅水放大」→「上岸成灾」的完整物理链条讲清楚，让没有物理基础的成年人或中学生一看就懂。**3D 不是装饰，是讲解主体**：每个关键概念都要在 3D 场景里被看见、被操控、被对照。

## 验收（可判定，逐条对应一条本机命令或一次浏览器实测）

1. `npm ci && npm run build` 退出码 0；生产构建产物可被本地静态服务打开，浏览器网络面板**外部域请求数 = 0**（字体、three、贴图一律本地化，禁止 CDN）。
2. 真实 Chrome 打开生产构建：`console error` 数 = 0，`pageerror` 数 = 0。
3. 主 3D 场景连续 60 帧采样：`requestAnimationFrame` 帧序号互不相同、时间戳严格递增（不得因切后台被节流而假通过）。
4. 物理正确性（单测 + 页面显示值一致）：`c = √(g·h)`，h=4000m 时 ≈198 m/s（≈713 km/h），h=10m 时 ≈9.9 m/s；Green 定律 `H₂/H₁ = (h₁/h₂)^(1/4)`，4000m→10m 得 ≈4.5 倍；波长/周期等数值**由公式算出**，不许硬编码结果字符串。
5. 概念覆盖完整（至少 7 个节点，每个在 3D 场景中有对应可视化 + 中文解说）：① 俯冲带逆断层错动 ② 海底垂向位移带动**整个水柱** ③ 深海长波：高速低幅、船不易察觉 ④ 地震波与海啸波速度差构成的预警窗口 ⑤ 浅水变形 shoaling：减速、波长压缩、波高放大 ⑥ 波前陡化与「海水先退」 ⑦ 多波列持续数小时与淹没范围。
6. 交互可用：播放/暂停/章节跳转、可调参数（震级或海底抬升量、海沟水深）并即时反映到 3D 与数值面板；键盘可达（Tab 焦点可见、空格播放暂停、方向键切章节）。
7. 响应式：1440×900 与 390×844 两个视口下无横向滚动条、文字不溢出、3D 画布占比合理。
8. 无障碍与对比度：正文文本对比度 ≥4.5:1、大字号 ≥3:1（逐组实算，不靠肉眼）；`prefers-reduced-motion` 下动画降级。
9. 中文文案无错别字、术语统一（海啸 / 波高 / 波长 / 水深 / 浅水变形 / 淹没），数字与单位规范。

## 背景与约束

- **本机**：macOS 26.4.1（arm64），Node v22.22.2 / npm 10.9.7，有 GPU；npm registry 可用（实测 `three` 最新 0.186.1、`vite` 8.3.5 可取）；无付费 API；可用本机真实 Chrome 做验收（需本地装 `playwright-core` 并以 `channel: chrome` 驱动）。
- **交付形态**：静态站点（vite 构建 → `dist`），依赖全部本地打包，**运行时外部请求数必须为 0**。
- **3D 技术前提**：Three.js + WebGL2；几何全部程序化生成（不引入外部 `.glb/.gltf` 资产）；海面用顶点位移 / 自定义 shader 表达波形；目标 60fps。
- **既有约定**：无（全新空仓库）。
- **已试过不行**：无。
- **本轮明确不做**：后端、数据库、登录、多语言、原生 App、CI（按流程验收以本机证据为准，不配 CI）。

## 内容准确性要求（硬）

- 讲解的物理机制必须与实际地球物理一致：海啸是**整个水柱运动的长波**，不是表面风浪；深海波高常不足 1 m 而波长可达 100–200 km；速度 `c=√(gh)`；浅水按 Green 定律放大；海啸常表现为「海水先退」而非单一巨浪；一次事件含多个波列、持续数小时。
- 引用的真实事件数据（如 2004 印度洋、2011 日本东北）需给出可核查来源（机构 / 报告名）并在页面标注；不确定的数字用「约」，不许写成精确值。
- 规划案中请给出**需核实的事实清单**与权威来源入口（NOAA/NCEI、USGS、UNESCO-IOC、日本气象厅、中国自然资源部海啸预警中心等），供执行方逐条查证。
